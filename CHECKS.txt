RAVOUT Render v2 — проверка перед передачей

37 автоматических тестов: PASS (Python 3.13, зависимости requirements.lock.txt).
Проверено:
- подпись Telegram, срок авторизации, изоляция заявок и приватных фото;
- запрет admin API обычному пользователю;
- создание, редактирование, замена фото, скрытие/публикация;
- валидация цены, категории, размера фото, формата файлов;
- сохранение качественного WebP без EXIF;
- категория + бренд + размер + цвет + диапазон цены совместно;
- сортировка, страницы, метаданные фильтров;
- миграция старой БД без удаления прежних товаров;
- очереди заявок, идемпотентность, избранное, статусы и сообщения менеджеру (Telegram API имитирован).

Chromium, 390x844 и 1280x900:
- сценарий администратора: добавить, редактировать, скрыть, опубликовать;
- бургер-меню, применение совместных фильтров и переход к результатам;
- избранное, карточка, крупное фото;
- заявка с фотографией, сохранение и история;
- проверка обычного покупателя: админ-вкладка скрыта, admin API -> 403;
- показ ошибки авторизации и ошибки слишком маленького фото;
- нет ошибок JavaScript и горизонтального переполнения в пройденных сценариях.

Визуально просмотрены мобильные экраны и широкоформатный вариант.
Исправлены двойная рамка поиска, контраст баннера, положение навигации и склонение счётчиков.
Тестовые товары и заявки были только в отдельной QA-базе и в архив не включены.

Ограничения проверки:
- реальный деплой Render с диском/доменом и реальная отправка Telegram не выполнялись без настроек владельца;
- проверка на настоящих Android/iOS устройствах внутри Telegram не выполнялась;
- перед публичным запуском нужны реальные фото товаров, правила магазина и политика данных.
