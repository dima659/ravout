# RAVOUT SHMOT · Render v2

Новая версия Mini App: спокойная типографика с локальными шрифтами, качественный баннер, карточки без обрезки фото, боковое меню фильтров и полноценная админ-вкладка. Бот, web и очередь отправки работают в одном сервисе.

## Обновить существующий сервис

1. Сделайте резервную копию постоянного диска/БД перед обновлением.
2. Распакуйте архив и загрузите **все файлы в корень GitHub**, с заменой одноимённых. Не загружайте только ZIP. Папки создавать не нужно — Docker соберёт структуру сам.
3. Особенно важно заменить `Dockerfile`, `core.py`, `main.py`, `index.html`, `style.css`, `app.js` и загрузить новые `hero.webp`, `sans-regular.ttf`, `sans-bold.ttf`, `FONT-LICENSE.txt`.
4. На Render оставьте Root Directory пустым, Dockerfile Path `./Dockerfile`, Docker Command без переопределения. Runtime — Docker, один Web Service, один экземпляр. Health Check Path — `/health`.
5. Сохраните прежние переменные окружения и тот же постоянный диск по тому же пути.
6. **Manual Deploy → Clear build cache & deploy**. Затем полностью закройте Mini App в Telegram и откройте заново.

Миграция добавляет в старый каталог только поля бренда, размеров и цветов. Товары, избранное и заявки не удаляются. Новые поля у прежних товаров сначала пустые — заполните их через админку. Без прежнего постоянного диска утраченные старые данные обновление не восстановит.

## Переменные Render

Значения задаются в **Environment** сервиса, не в GitHub и не в переписке:

```
BOT_TOKEN=настоящий_токен_из_BotFather
ADMIN_IDS=ваш_числовой_Telegram_ID
MANAGER_CHAT_ID=числовой_ID_чата_менеджера
WEBAPP_URL=https://адрес-вашего-сервиса.onrender.com
RUN_BOT=true
DEV_MODE=false
DATA_DIR=/var/data
```

Это шаблон, строки-заглушки нужно заменить! `ADMIN_IDS` — положительные числа через запятую, не username. В `MANAGER_CHAT_ID` можно указать свой ID, если вы менеджер; для группы указывается её ID со знаком минус. Username в этих двух переменных не подходит. В профиле приложения теперь показывается ID вошедшего пользователя.

На Render подключите **Persistent Disk** с Mount Path `/var/data` (платный тариф с поддержкой дисков). Без постоянного диска фото и база могут исчезнуть при деплое/перезапуске. Засыпающий бесплатный сервис не подходит для надёжной круглосуточной работы polling-бота. Диск и резервные копии доступны только владельцу.

Один токен должен опрашиваться только одним экземпляром бота. Не запускайте дополнительный Worker и не оставляйте прежний polling-процесс включённым. Ранее настроенный webhook нужно отключить до polling; проект не меняет чужие webhook-настройки автоматически. Менеджер должен открыть бота и нажать «Старт», чтобы получать заявки.

## Админка прямо в Mini App

Администратор видит вкладку **«Админ»** снизу и кнопку **«Управление магазином»** в профиле. Покупатель их не видит. Даже прямой запрос к admin API без соответствующего Telegram ID получает 403: защита проверяется на сервере, а не только в интерфейсе.

Если вкладки нет:

1. Проверьте ID в профиле Mini App.
2. Укажите этот числовой ID в `ADMIN_IDS` на Render.
3. Сохраните Environment с перезапуском, закройте Mini App и откройте заново.

### Добавить товар

1. «Админ» → «Добавить товар».
2. Выберите **оригинальное фото** с телефона/компьютера.
3. Заполните название, цену целым числом в рублях, категорию; по желанию бренд и описание.
4. Размеры и цвета укажите через запятую: `S, M, L` / `Чёрный, Красный`.
5. Включите «Опубликовать в каталоге» и нажмите «Сохранить товар».

### Изменить / заменить фото / скрыть

В списке товаров нажмите «Изменить», отредактируйте поля и сохраните. Для нового фото нажмите на область изображения. Без выбора нового файла сохраняется прежнее фото. Кнопка «Скрыть» убирает товар из витрины, «Опубликовать» возвращает его. Жёсткое удаление не применяется, чтобы не ломать историю заявок. Список можно искать по названию/бренду и фильтровать по публикации; доступна загрузка следующих страниц.

### Качество фотографий

- JPG, PNG, WebP, до 15 МБ, минимум **600×600 px**, максимум 36 мегапикселей.
- При загрузке сохраняется версия до 2560 px по длинной стороне в WebP с качеством 94; маленькие исходники не увеличиваются.
- EXIF удаляется, ориентация исправляется, прозрачный фон кладётся на белый.
- Карточки показывают вещь целиком, не обрезая её по краям. Нажмите фото в карточке для крупного просмотра.
- Старые размытые фотографии сами не станут чёткими — замените их оригиналами через редактор.
- Не отправляйте фото сначала как сжатую картинку в Telegram: выбирайте оригинал непосредственно в админке.

Баннер `hero.webp` — новая AI-сгенерированная иллюстративная streetwear-композиция, не обещание наличия этих вещей. Реальных товаров и цен в начальную базу не добавлено. Старый растянутый логотип из скриншота в интерфейсе больше не используется.

## Фильтры через бургер-меню

Кнопка ☰ в шапке или значок настроек рядом с поиском открывает боковое меню:

- категория;
- бренд;
- цена «От» / «До»;
- размер;
- цвет;
- сортировка: новые, дешевле, дороже, по названию.

Параметры работают **совместно на сервере**. Бренды, размеры и цвета предлагаются из опубликованных товаров. Введите «От» не выше «До». «Показать вещи» применяет условия и прокручивает к результатам. «Сбросить» очищает поля меню; чтобы применить сброс, нажмите «Показать вещи». Активные условия видны отдельными метками, их можно снимать по одному. Текстовый поиск не очищается при сбросе фильтров — его можно удалить в строке поиска.

Витрина загружает товары страницами по 40, админка — по 50. Для следующих страниц есть «Показать ещё». Фильтры не влияют на независимый список избранного.

## Заявки и команды бота

Форма принимает до 3 фото по 5 МБ, описание/ссылку, размер, цвет, бюджет и количество. Фото заявок приватные и доступны владельцу или администратору. Заявка сохраняется в SQLite прежде отправки менеджеру; повтор той же отправки не создаёт новую заявку. Ограничение — 10 заявок в час на пользователя.

Менеджер вручную подбирает вещь. Автоматический AI-поиск и платежи не включены. Заказ, наличие, доставку и итоговую стоимость подтверждает менеджер. При сетевом сбое возможен повтор Telegram-уведомления с тем же номером; сохранённая заявка не теряется. `/requests` показывает очередь, `/retry ID` повторяет доставку. `/health` проверяет web и БД, а не доставку Telegram.

Команды администратора сохранены:

```
/admin
/products
/requests
/status 1 working
/status 1 done
/status 1 cancelled
/retry 1
/id
```

Можно по-прежнему добавлять товар фото-сообщением с подписью:

```
/add Название | 15000 | Одежда | Описание
```

Для лучшего качества, бренда, размеров и цветов удобнее новая админка. Категории: Одежда, Обувь, Сумки, Аксессуары.

## Данные и эксплуатация

Не меняйте DATA_DIR и не удаляйте диск при обновлении. Делайте согласованные резервные копии базы и файлов, остановив запись на время копии. Старые файлы фото после замены остаются на диске, чтобы не ломать уже открытые карточки; их очистка требует проверки неиспользуемых ссылок и резервной копии.

До публичного запуска разместите контакты владельца магазина, условия заказа, доставки/возврата и политику обработки данных с конкретными сроками. Экран обработки данных — пояснение, не готовая юридическая политика. Автоматическое удаление по сроку не реализовано; запросы на удаление обрабатывает владелец с подтверждением личности и учётом обязательного хранения. Не собирайте документы и платёжные данные через форму.

Шрифты Liberation Sans включены локально, без зависимости от Google Fonts; лицензия — FONT-LICENSE.txt. Контейнер, как и прежняя Render-версия, работает с пользователем по умолчанию образа для записи на подключённый диск.

Проверка описана в CHECKS.txt. Реальная публикация Render и доставка с вашим токеном требуют проверки владельцем после деплоя.
