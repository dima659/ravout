# RAVOUT SHMOT · Telegram Mini App

Рабочий исходный проект по приложенному макету. Backend и бот — Python; экран внутри Telegram — HTML/CSS/JS. Это не уже опубликованный бот: для работы в Telegram нужно подключить собственные настройки и развернуть сервер.

## Что реализовано

- Каталог, поиск, фильтры, карточка товара; цены в рублях.
- Избранное с привязкой к проверенному Telegram ID.
- Заявка по фото, описанию либо на товар. До 3 фото по 5 МБ, параметры размера, цвета, бюджета, количества, ссылка и контакт.
- Сохранение в SQLite, защита от повторного создания при повторной отправке, ограничение 10 заявок в час на пользователя.
- Проверка подписи и срока Telegram initData на сервере. Frontend не является источником доверенных ID.
- Фото заявок закрыты авторизацией, доступны владельцу и администраторам. EXIF удаляется при пересохранении.
- Устойчивая очередь отправки менеджеру с повторами и видимым состоянием доставки.
- «Мои заявки», фото, статусы; смена статуса менеджером, уведомление покупателю.
- Управление каталогом и заявками через команды бота. Нет выдуманных товаров и цен.

**Подбор по фото выполняет менеджер, как в макете. Автоматический поиск через AI/маркетплейсы и приём платежей не включены.** Заявка — не оплаченный заказ. Итоговую цену и доставку подтверждает менеджер.

## 1. Локальный просмотр без Telegram

Для быстрого запуска: `start-demo.bat` на Windows или `./start-demo.sh` на Linux/macOS (нужен установленный Python 3.12+). Ниже — команды вручную.

Python 3.12+:

```bash
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.lock.txt
DEV_MODE=true uvicorn app.main:app --host 127.0.0.1 --port 8000
```

Откройте http://127.0.0.1:8000. Демо запускается только локально, использует пользователя ID 1, показывает предупреждение. Заявки сохраняются, но без токена и чата менеджера никуда не отправляются. Кнопки и формы работают, каталог изначально пуст. Не выставляйте деморежим в интернет. Для локального просмотра заполненный `.env` не нужен.

На Windows PowerShell: `$env:DEV_MODE="true"; python -m uvicorn app.main:app --host 127.0.0.1 --port 8000`.

## 2. Создайте бота и получите свои ID

1. В @BotFather выполните `/newbot`, скопируйте токен **только в свой `.env`**. Не отправляйте его в чат и не кладите в репозиторий.
2. Узнать свой числовой Telegram ID можно у @userinfobot. Он нужен для `ADMIN_IDS`. Для личных уведомлений менеджеру его ID можно использовать и в `MANAGER_CHAT_ID`.
3. Менеджер должен открыть созданного бота и нажать «Старт», иначе бот не сможет написать ему первым. Для группы: добавьте бота в закрытую группу, запустите его, отправьте `/id@имя_бота`; используйте ID группы со знаком минус. Указанные в `ADMIN_IDS` люди получают право менять заявки.
4. Купите/подключите домен, направьте A-запись на IP сервера (AAAA — только если сервер действительно обслуживает IPv6). Откройте входящие 80/443. Понадобится VPS с Docker Compose.

## 3. Развёртывание с HTTPS

```bash
cp .env.example .env
# Отредактируйте .env на сервере:
# BOT_TOKEN=ваш_токен
# ADMIN_IDS=ваш_числовой_ID
# MANAGER_CHAT_ID=ID_чата_менеджера
# WEBAPP_URL=https://ваш.домен
# DOMAIN=ваш.домен  (без https://)
# DEV_MODE=false

docker compose up -d --build
docker compose logs --tail=50 web bot caddy
```

Caddy автоматически получает TLS-сертификат, если DNS и порты настроены. Compose принудительно выключает DEV_MODE у web. Токен доступен лишь серверным процессам, не браузеру. Один экземпляр web обслуживает очередь, один экземпляр bot — long polling. Не запускайте второй poller с тем же токеном. Если токен ранее использовался webhook-ботом, отключите прежний сервис и удалите webhook через Telegram Bot API перед запуском polling (не удаляйте накопленные обновления без необходимости).

Для начальной настройки команда `/start` в личном чате отдаст кнопку «Открыть магазин». Кнопка меню настраивается ботом автоматически. В BotFather можно дополнительно настроить Main Mini App и описание, но это не требуется для кнопки из `/start`.

Для запуска без Docker экспортируйте переменные окружения и отдельно запустите:

```bash
uvicorn app.main:app --host 127.0.0.1 --port 8000 --workers 1
python -m app.bot
```

Нужен собственный HTTPS reverse proxy с ограничением тела запроса 17 МБ. Сам по себе `.env` вне Compose не подхватывается: загрузите его в окружение доверенным способом. `DATA_DIR` должен быть одинаковым для двух процессов и доступным для записи.

## 4. Наполните каталог

Администратор в личном чате отправляет `/admin`.

Отправьте **фото с подписью** (не файл-документ):

```
/add Название вещи | 15000 | Одежда | Описание, размеры и особенности
```

Цену указывайте целым числом в рублях без пробелов. Категории: `Одежда`, `Обувь`, `Сумки`, `Аксессуары`.

Команды:

```
/products
/edit 1 | Новое название | 16000 | Одежда | Новое описание
/hide 1
/show 1
/requests
/status 1 working
/status 1 done
/status 1 cancelled
/retry 1
```

Для замены фото скройте старый товар и добавьте новый с фото. Старый сохраняется для истории заявок. Список `/products` показывает последние 50 товаров, витрина — до 200 подходящих товаров, профиль — до 100 заявок; это версия для небольшого магазина, без пагинации и большой нагрузки.

## Доставка и эксплуатация

SQLite и фото хранятся в постоянном томе `shop-data`. Не запускайте `docker compose down -v`: это удаляет данные. Делайте резервные копии всего тома; перед файловой копией остановите web и bot, чтобы согласованно сохранить SQLite и фото. Доступ к VPS и резервным копиям должен быть только у владельца.

Отправка менеджеру работает по принципу at-least-once. При редком сбое сети после принятия сообщения Telegram возможен дубль уведомления с тем же номером заявки. Ошибки доставки не теряют заявку: повторные попытки выполняются с задержкой до часа. `/requests` показывает очередь, `/retry ID` принудительно повторяет доставку. Проверяйте, что бот добавлен в чат, не заблокирован и имеет права отправлять фото и сообщения.

Если initData старше суток, нужно заново открыть приложение из бота. Одновременно не открывайте один токен в нескольких poller-процессах. Для больших нагрузок понадобятся PostgreSQL, распределённый rate limiting, отдельная очередь и мониторинг.

## Данные и материалы

Графика персонажа извлечена из предоставленного изображения, поэтому её разрешение ограничено исходным макетом. Для резкого изображения на больших экранах замените `static/assets/brand.png` оригиналом с белым фоном. Логотип интерфейса выполнен текстом в близком стиле.

Перед публичным запуском разместите контакты магазина и оператора персональных данных, политику с конкретным сроком хранения, условия заказа/доставки/возврата. Встроенный экран обработки данных — пояснение, не готовая юридическая политика. Не собирайте платёжные данные в форме заявки.

Удаление по запросу владельцем: сначала сохраните необходимые по закону записи, затем удалите фото из `data/private`, соответствующие строки `photos`, `outbox`, `requests`, `favorites` через SQLite в транзакции. ID пользователя должен быть подтверждён. Не удаляйте общий каталог. Автоматическое хранение по сроку и кнопка удаления не реализованы.

## Проверка

`requirements.lock.txt` содержит версии, на которых выполнялась проверка (Python 3.13); Docker использует именно их. `requirements.txt` задаёт допустимые диапазоны для осознанного обновления зависимостей.

```bash
python -m unittest discover -s tests -v
```

Тесты используют временную БД и проверяют подпись, изоляцию данных, заявки, фото, идемпотентность и избранное. Реальную доставку Telegram нужно проверить после подключения своего токена:

1. `/start`, открытие Mini App внутри Telegram.
2. Добавление товара фото-командой, поиск, фильтр, избранное.
3. Отправка заявки с фото, получение её менеджером.
4. Смена статуса кнопкой менеджера и уведомление клиенту.
5. После перезапуска сервисов данные остаются.
6. При временном отключении менеджера заявка сохраняется и остаётся в очереди.

До подключения токена и домена проект не является запущенным Telegram-магазином.
