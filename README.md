# RAVOUT SHMOT — версия для Render

## Что исправлено

Все файлы архива находятся **в корне**, без вложенных папок. При сборке Docker сам создаёт `app/`, `static/` и `static/assets/`. Простая загрузка всех распакованных файлов в GitHub теперь не ломает структуру.

Mini App, бот long polling и очередь уведомлений запускаются в одном Docker Web Service, поэтому видят одну базу и фотографии. Отдельный Worker, Compose и Caddy на Render не нужны. Приложение слушает PORT, назначенный Render.

## Загрузка

1. Распакуйте архив.
2. В GitHub замените одноимённые файлы **новыми из этого архива**, включая Dockerfile, main.py и bot.py. Все эти файлы должны остаться в корне репозитория. Архив ZIP вместо исходников загружать не нужно.
3. Старые Caddyfile, compose.yaml и инструкции запуска из предыдущего архива можно удалить — для этой версии они не нужны.

## Настройка Render

Один **Web Service**, runtime **Docker**:

- Root Directory: **пусто**.
- Dockerfile Path: `./Dockerfile`.
- Docker Build Context Directory: корень репозитория, если поле предлагается.
- Health Check Path: `/health`.
- Один экземпляр сервиса, без горизонтального масштабирования.
- Docker Command: не переопределяйте; используется CMD из Dockerfile.

### Environment

Задайте в панели Render (не в GitHub):

```
BOT_TOKEN=токен_из_BotFather
ADMIN_IDS=ваш_числовой_telegram_id
MANAGER_CHAT_ID=числовой_id_чата_менеджера
WEBAPP_URL=https://имя-вашего-сервиса.onrender.com
RUN_BOT=true
DEV_MODE=false
DATA_DIR=/var/data
```

`WEBAPP_URL` замените реальным внешним адресом, который показывает Render. `ADMIN_IDS` допускает несколько чисел через запятую. Не задавайте DATA_DIR на папку исходников.

Токен нельзя публиковать в репозитории или переписке. Если он уже опубликован — перевыпустите через BotFather.

### Постоянный диск

Для сохранения SQLite и загруженных фото добавьте **Persistent Disk** с Mount Path `/var/data` (например, 1 GB). Постоянные диски требуют поддерживающего их платного тарифа Render. Без диска данные контейнера могут исчезнуть при деплое или перезапуске. Бесплатный засыпающий сервис не подходит для надёжного постоянно работающего polling-бота.

Контейнер работает с пользователем по умолчанию образа, чтобы писать на подключённый Render-диск. Это упрощённая конфигурация развёртывания; не публикуйте порт БД и не давайте посторонним доступ к диску или настройкам сервиса.

После загрузки и настройки: **Manual Deploy → Clear build cache & deploy**.

Если на первом деплое ещё неизвестен адрес, дождитесь появления URL сервиса в панели, внесите его в WEBAPP_URL и повторите деплой. Приложение специально не стартует в production с незаполненными обязательными настройками.

## Подключение Telegram

1. Менеджер должен открыть бота и нажать «Старт». Иначе бот не сможет написать первым.
2. В личном чате с ботом отправьте `/start`. Кнопка откроет Mini App. Кнопка меню устанавливается автоматически.
3. Администратор отправляет `/admin` и получает инструкции по управлению каталогом.
4. Отправьте менеджеру тестовую заявку из приложения и проверьте смену статуса.

Только один сервис должен опрашивать этот токен. Остановите старые экземпляры бота. Если для токена ранее настроен webhook, отключите старый webhook перед polling. Данный проект не удаляет чужие настройки автоматически.

Если в логах есть `Telegram polling interrupted`, проверьте токен, сетевое соединение и отсутствие другого poller/webhook. `/health` проверяет web и базу, не подтверждает доставку Telegram. Очередь можно проверить через `/requests`.

## Каталог и заявки

Начальный каталог пуст, реальные товары добавляет администратор. Отправьте боту фото с подписью:

```
/add Название | 15000 | Одежда | Описание
```

Категории: Одежда, Обувь, Сумки, Аксессуары. Цена — целое число в рублях.

```
/products
/edit 1 | Новое название | 16000 | Одежда | Описание
/hide 1
/show 1
/requests
/status 1 working
/status 1 done
/status 1 cancelled
/retry 1
/id
```

Форма принимает до 3 фото по 5 МБ, описание, ссылку, размер, цвет, бюджет, количество. Избранное, история и приватные фото привязаны к подписанному Telegram ID. Заявки сохраняются до отправки менеджеру. Сетевые сбои приводят к повторной доставке; редкий дубль уведомления с тем же номером возможен. Подбор выполняет человек, AI-поиск и оплата не включены.

## Ограничения и данные

Версия для небольшого магазина: витрина показывает до 200 подходящих товаров, профиль — до 100 заявок, команда /products — до 50 товаров. Не масштабируйте SQLite-вариант на несколько сервисов. Регулярно резервируйте постоянный диск и защищайте доступ к нему.

Для удаления данных по подтверждённому запросу владельца администратор удаляет соответствующие строки photos/outbox/requests/favorites и связанные файлы private с учётом обязательного хранения. Автоматическое удаление по сроку не реализовано. До публичного запуска разместите контакты владельца, условия заказа и политику обработки данных с конкретными сроками.

Изображение персонажа извлечено из исходного макета; для лучшего качества замените brand.png оригиналом. В архиве нет токенов, реальных товаров и персональных данных.

Исходники в этом архиве имеют плоскую структуру для GitHub-загрузки. Для ручного запуска без Docker сначала разместите main.py/core.py/bot.py/__init__.py в app/, HTML/CSS/JS — в static/, brand.png — в static/assets/, затем запустите `python start.py`. Не запускайте `python main.py`: этот модуль использует относительные импорты.
